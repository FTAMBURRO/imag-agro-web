5. TECNOLOGÍA Y PORTABILIDAD

Construir el proyecto con:

- Next.js con App Router.
- TypeScript en modo estricto.
- Tailwind CSS.
- React Server Components por defecto.
- Client Components únicamente para interacciones que los necesiten.
- Framer Motion o Motion únicamente para animaciones puntuales y optimizadas.
- Lucide React para iconos.
- Zod para validaciones si se implementan formularios.
- ESLint.
- Prettier.
- next/image para imágenes.
- next/font para tipografías.
- Metadata API nativa de Next.js.
- npm como administrador de paquetes.

No utilizar:

- Replit Database.
- Replit Auth.
- Replit Object Storage.
- URLs internas de Replit.
- Dependencias propietarias de Replit.
- Archivos guardados dinámicamente en el filesystem.
- Un servidor Express personalizado.
- Código que dependa del dominio replit.dev o replit.app.
- Servicios que dificulten la migración.
- Componentes completos copiados sin criterio desde una librería visual.

El proyecto debe funcionar mediante comandos estándar:

- npm run dev
- npm run build
- npm run start
- npm run lint
- npm run typecheck

Configurar desarrollo y producción para escuchar correctamente el puerto proporcionado por el entorno.

Si Replit necesita un archivo `.replit`, puede crearse solamente para facilitar la ejecución dentro de Replit. Ninguna función esencial debe depender de ese archivo.

No crear `vercel.json` salvo que exista una necesidad real. Next.js debe poder ser detectado y desplegado automáticamente por Vercel.

Mantener todo el proyecto sincronizable con GitHub.
